# Сравнение стратегий массовой загрузки данных в PostgreSQL

## 1. Цель эксперимента

Сравнить время массовой загрузки данных двумя способами:
- пакетные SQL-команды INSERT;
- COPY FROM CSV.

## 2. Среда эксперимента

- СУБД: PostgreSQL 16.15.
- Таблица: bulk_load_benchmark.
- Количество строк: 50 000.
- Источник данных: один CSV-файл, сформированный генератором generate_data.py.
- Первичный ключ: id.
- Размер пакета INSERT: 500 строк.
- Все пакетные INSERT выполняются в одной транзакции.

## 3. Методика

1. Генерируется фиксированный набор из 50 000 строк.
2. Перед каждым замером таблица очищается командой TRUNCATE.
3. Для INSERT заранее формируется SQL-файл с пакетами по 500 строк.
4. Все INSERT выполняются одним процессом psql в одной транзакции.
5. Для COPY тот же CSV загружается командой COPY через psql.
6. Очистка таблицы, генерация CSV и подготовка SQL не входят во время загрузки.
7. Время измеряется на стороне клиента и включает запуск psql и передачу данных.
8. Каждая стратегия измеряется три раза.

## 4. Результаты

| № | Пакетный INSERT, с | COPY FROM CSV, с |
|---:|---:|---:|
| 1 | 0.928 | 0.643 |
| 2 | 0.856 | 0.529 |
| 3 | 0.948 | 0.534 |
| Среднее | 0.911 | 0.569 |
| Медиана | 0.928 | 0.534 |

Среднее время INSERT: 0.911 секунды.

Среднее время COPY: 0.569 секунды.

Отношение среднего времени INSERT к COPY: приблизительно 1.60.

COPY загрузил данные примерно в 1.60 раза быстрее. Среднее время загрузки уменьшилось примерно на 37.5%.

## 5. Проверка корректности

После загрузки проверяются:
- общее количество строк;
- минимальное значение id;
- максимальное значение id.

Ожидаемый результат: 50 000 строк, минимальный id = 1, максимальный id = 50000.

## 6. Вывод

В проведённом эксперименте COPY FROM CSV оказался быстрее пакетного INSERT.

COPY предназначен для массовой загрузки и обрабатывает набор данных как одну операцию. В выбранной реализации INSERT данные передаются 100 отдельными SQL-командами внутри одной транзакции, что создаёт дополнительные накладные расходы.

Результаты относятся к конкретной конфигурации и методике эксперимента. Они не означают, что COPY всегда будет быстрее при любых объёмах данных и условиях.
