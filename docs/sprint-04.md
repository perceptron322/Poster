# Спринт 4

## Безопасность PostgreSQL и репликация

### Цель спринта

Настроить защищённое подключение к PostgreSQL, организовать потоковую репликацию базы данных и разграничить права пользователей в зависимости от их роли.

### 1. Настройка TLS

Для основного экземпляра PostgreSQL настроено шифрование TCP-соединений с использованием TLS.

Реализовано:
- Генерация сертификата и закрытого ключа при запуске контейнера.
- Включение SSL в PostgreSQL.
- Настройка `pg_hba.conf` для отклонения незашифрованных TCP-подключений.
- Разрешение зашифрованных подключений с парольной аутентификацией SCRAM-SHA-256.
- Проверка подключения с TLS и проверка отказа при отключённом SSL.

Для клиентских TCP-подключений используется параметр `sslmode=require`.

### 2. Настройка read replica

В Docker Compose добавлен отдельный экземпляр PostgreSQL для репликации — `replica`.

Основные параметры:
- Основная база данных доступна на порту `5433` хоста.
- Реплика доступна на порту `5434` хоста.
- Для реплики используется отдельный том `replicadata`.
- Первичная копия данных создаётся с помощью `pg_basebackup`.
- Для передачи изменений используется потоковая репликация WAL.
- Для репликации создана отдельная роль `replicator`.
- Реплика работает в режиме восстановления и доступна только для чтения.
- Репликационное соединение с основной базой использует TLS.

Работоспособность проверена запросом `SELECT pg_is_in_recovery()`, состоянием репликации на основном сервере и сравнением данных между основной базой и репликой.

### 3. Разграничение прав пользователей

Созданы три пользовательские роли PostgreSQL:

- `admin_user` — административные операции в пределах выданных прав.
- `app_user` — чтение и изменение данных без права создавать таблицы.
- `analyst_user` — чтение данных и выполнение аналитических запросов без права изменять данные.

Дополнительно создана роль `replicator`, предназначенная для потоковой репликации.

Для настройки ролей используется SQL-скрипт `scripts/security/roles.sql`. Переменные окружения для паролей описаны в `.env.example`, а локальные секреты хранятся в `.env`.

### 4. Автоматизация и проверка

Для настройки окружения используются Docker Compose и Makefile.

Основные файлы:
- `docker-compose.yml` — описание основной базы данных и реплики.
- `config/postgres/pg_hba.conf` — правила доступа к PostgreSQL.
- `scripts/postgres/replica-entrypoint.sh` — подготовка и запуск реплики.
- `scripts/security/roles.sql` — создание ролей и настройка привилегий.
- `scripts/security/demo.sh` — демонстрация разрешённых и запрещённых операций.
- `.env.example` — пример необходимых переменных окружения.

Проверки подтвердили:
- Основной экземпляр и реплика находятся в состоянии `healthy`.
- Незашифрованные TCP-подключения к основной базе отклоняются.
- Зашифрованные подключения работают.
- Изменения основной базы передаются на реплику.
- Реплика не принимает операции записи.
- `app_user`, `analyst_user` и `admin_user` имеют разные уровни доступа.
- Демонстрационный скрипт завершается успешно при ожидаемом поведении ролей.

### Результат спринта

Настроена защищённая конфигурация PostgreSQL с TLS, потоковой репликацией и разграничением прав доступа. Подготовлены скрипты для запуска реплики и проверки прав пользователей.

**Ограничение текущей реализации:** автоматическая маршрутизация аналитических запросов приложения на read replica в рамках выполненных изменений не реализована. Аналитические запросы проверялись непосредственно под ролью `analyst_user`.
